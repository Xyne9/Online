## 三、本轮修复的真缺陷（全部来自实跑暴露，不是猜的）

### 3.1 【架构级】网关白名单 `/api/*/health` 误放行 `/api/admin/health`

`oj-gateway` 的 `whitelist` 里有一条 `/api/*/health`，`AntPathMatcher` 会匹配 `/api/admin/health`。后果是**网关跳过 JWT 校验、不注入 `X-User-Role`**，admin 服务收到"无身份头"→ 401。

表现极具误导性：**管理员拿着有效 token 也进不了管理端**，而且日志里只有一行 401，看不出是网关放行的。

更危险的是反向情形：一旦哪天 `/api/admin/health` 被写成"无头即放行"，这条通配就等于**把全站健康大盘裸奔到公网**。

**修法**：白名单逐条列出 4 个无库业务服务的探活端点（`/api/teaching/health` 等），删掉通配，并在 yml 里写了 12 行注释说明为什么不能用通配。

### 3.2 【安全级】`AdminGuard` 把 401 和 403 合并了

原实现一律抛 403。契约 §2.8 要求：**无身份头 → 401、有身份非 ADMIN → 403**。

这不只是语义不精确：前端 `api/http.js` 收 401 会**清 token 并跳登录页**，收 403 只弹"没有权限"。合并的后果是 **token 真过期时用户卡在页面上反复点，永远等不到自动跳登录**。

### 3.3 【数据级】`#54` 易错题排行下发 `题目 N` + `difficulty:null`

`AnalyticsService.load()` 原本只从 `teach_assignment.problem_ids` 灌 `problemMeta`。而 `judge_submission` 里 **103/119 条是 `assignment_id=0` 的自由练习提交**——这些题的标题与难度从来没被加载过。

实测现象：
```
#54 → {problemId:1024, title:"题目 1024", difficulty:null}
DB   → 1024 = 最大异或和(难度3)
```

前端拿到 `null` 难度，难度徽标直接空掉。

**修法**：`problemMeta` 的取数集合改为「活动题单 ∪ 本次统计出现的全部 `submission.problem_id`」。**没有**往 `data.problems` 里塞自由练习的题——那是"应做题"的语义，塞进去会让 `#58` 的 `solved/total` 分母虚高。

### 3.4 【功能级】`#75` 部分更新全部 400

`ChannelCommandDTO.roleBindings` 的默认值是 `new ArrayList<>()` 而非 `null`，于是「没传」和「传了空数组」不可区分：

```java
if (dto.getRoleBindings() != null) {   // 空 List 也满足
    normalizeRoles(...)                 // 抛「不能为空」→ 400
}
```

**任何不含 roleBindings 的局部更新全部被拒**——正好打中契约 §7.2.4「部分更新」的定义。改成 `null` 默认后语义分得开：不传=null=不动；显式传 `[]`=空数组=由 `normalizeRoles` 拒绝（正确，创建/更新都不允许零角色）。

### 3.5 【一致性】审计导出限流 key 是业务代码拼的私货

`AdminAuditController` 原来用 `RedisKeys.PREFIX + "admin:audit:export"` 自己拼。前缀虽取自常量，但整串仍是私货，别的服务要查这条锁得再抄一遍拼法（违反 agent.md §4.4）。

**修法**：收敛进 `RedisKeys` 第 13 类 `adminAuditExport()` + `TTL_ADMIN_AUDIT_EXPORT`，并让 `AdminProperties.exportRateLimitSeconds` 的默认值引用同一个常量（避免「常量 60、配置 30」的漂移）。

## 四、前端联调中抓到的 5 个真缺陷

这些都是**只有看真实数据才能发现**的——纯读源码或看 mock 都发现不了。

### 4.1 `ttftPeak = NaN`（`a-models`）

`acc[i] = ...` 构造的是**稀疏数组**，`Array.prototype.map` 会**跳过空洞**留下 `undefined`，`Math.max(...undefined)` = `NaN`。整个「峰值/均值 TTFT」两块全变 NaN，但**页面不报错**，只是默默显示 NaN。

**修法**：按 `0..maxHour` 定长补 0 再聚合。

### 4.2 知识点全渲染成 `null%` 且全被涂成薄弱色

`null < 50 === true` —— "没有数据"的知识点反而被涂成**薄弱色**，看起来像"这十个知识点都特别差"。比白屏更具迷惑性。

两处同源镜像：
- `s-analytics`：`#62 weakKps` 只给最弱 5 个，其余 `pct=null` → 显示 `—`、条形 `scaleX(0)`、不涂薄弱色，**绝不拿班级值冒充个人值**
- `t-analytics`：班级页的"掌握度"**就是班级掌握度**，应传 `k.masteryPercent` 而不是 `null`

### 4.3 `t-dashboard` 引用未定义的 `stats`

删掉对 `#87` 的调用后，计算 `fallbackRate` 那段仍引用 `stats` → `ReferenceError` → 整页 `loadErr=true`。

顺带确认了一件重要的事：**`#87 /api/admin/stats` 是 ADMIN 专属，教师账号 403**。所以教师工作台的"云端/本地路由分布"**根本没有合法数据源**（`#56`/`#61` 都不下发）。已如实隐藏并改文案，不再画假的 72/21/7。

### 4.4 CSV 导出 401 不触发登出

`http.js` 的 `opts.raw` **直接返回 Response，不走信封解包**，也就没有 401 处理。导出时 token 过期会显示"导出失败（HTTP 401）"而不是引导重新登录。已在 `exportCalls` 里自己补 401 分支。

### 4.5 `Content-Disposition` 解析优先级反了

正则 `/filename\*?=/` 会**先匹配到 `filename=`**，而后端实际下发：
```
attachment; filename="ai-calls-202610272327.csv"; filename*=UTF-8''ai-calls-202610272327.csv
```
`filename=` 是给老客户端的 ASCII 兜底（中文名会被替换成 `???`），`filename*=` 才是原文。**改成优先 `filename*=`**，取不到再退普通名。

## 七、本步新增的「不知道就一定踩」硬事实

### 7.1 `redis-cli FLUSHDB` 会连带清掉展示号序列，造成 `Duplicate entry`

排障时为了清登录限流跑了 `FLUSHDB`，结果 `oj:seq:{biz}` 全部归零，下一次提交/建活动/建查重任务就拿到 `S-1`/`A-0001`/`PL-0001`，与历史行**唯一键冲突** → `DuplicateKeyException` → 500。

```
Duplicate entry 'S-1' for key 'judge_submission.display_no'
Duplicate entry 'PL-0002' for key 'teach_plagiarism_task.display_no'
```

**正确做法**：只删单个 key（`DEL oj:rate:login:127.0.0.1`），**绝不用 `FLUSHDB`/`FLUSHALL`**。
已经误删时，按库内各表 `display_no` 的最大值重新 SET：

```sql
-- 四个序列各自的最大值（注意 PL- 前缀长度 3，SUBSTRING 从 4 位起）
SELECT MAX(CAST(SUBSTRING(display_no,3) AS UNSIGNED)) FROM judge_submission        WHERE display_no REGEXP '^S-[0-9]+$';
SELECT MAX(CAST(SUBSTRING(display_no,3) AS UNSIGNED)) FROM teach_assignment       WHERE display_no REGEXP '^A-[0-9]+$';
SELECT MAX(CAST(SUBSTRING(display_no,4) AS UNSIGNED)) FROM teach_plagiarism_task  WHERE display_no REGEXP '^PL-[0-9]+$';
SELECT MAX(CAST(SUBSTRING(display_no,3) AS UNSIGNED)) FROM teach_plagiarism_report WHERE display_no REGEXP '^P-[0-9]+$';
```
```powershell
docker exec oj-cloud-redis redis-cli SET oj:seq:submission <max>
docker exec oj-cloud-redis redis-cli SET oj:seq:assignment <max>
docker exec oj-cloud-redis redis-cli SET oj:seq:plagiarism <max>          # 报告用
docker exec oj-cloud-redis redis-cli SET oj:seq:plagiarism_task <max>     # 任务用，**与报告是两个 key**
```

> ⚠️ 注意查重是**两个独立序列**：`oj:seq:plagiarism`（报告 `P-0001`）与 `oj:seq:plagiarism_task`（任务 `PL-0001`）。只补一个还会撞。

### 7.2 `#81 ttftMs` 为 null 是正确语义，不是丢字段

`ai_chat_record.ttft_ms` 有 11 条 null，**全部是 `guardrail_action=1`（JAILBREAK 拦截）**——根本没发给模型，自然没有首 token 时间。

验收断言必须写成「非负整数或 null，且 `guardAction≠1` 时不允许 null」，否则会把正确语义判红。

### 7.3 单会话 token + 手工验证 = 验收中途集体 401

跑 `verify-day17.py` 时如果同时有人在手工 curl admin 端点，管理端断言会突然 `76/80/81/83~87` 一起 401，看起来像后端崩了。

已给探针加自愈（401 且用 admin token → 自动重登 1 次，上限 3 次）。**但根因是串行约束**：验收期间不要手工登同一账号。

### 7.4 智谱当前是 200 不是 429（agent.md §2.6 那条记录已过期）

实测 `glm-5.3-flash` 返回 **HTTP 200**，但 `content` 为空、8 个 token 全被 `reasoning_content` 吃掉。所以判活标准必须是「2xx + `choices` 非空」，**不能看正文是否为空**——否则推理模型会被永久误判 DEGRADE。

### 7.5 契约与 DDL 的一处偏差：`log_ref`

`docs/02 §8.7` 写 `log_ref VARCHAR(255) 日志落盘路径`，库里实际是 **`TEXT` 存日志文本本身**。
**以库为准**（改 DDL 要重建数据卷，成本远大于收益），`#85` 按"整段文本切行取最后 N 行"实现。

### 10.2 沙箱终止连接真实执行

原实现仅由 admin 更新实例表；判题提交统一写 `sbx-local`，没有为每次执行登记实例。
旧 `verify-day17.py` 自造 RUNNING 数据行后检查 UPDATE 成功，无法证明运行进程被终止。

现在提交记录与独立 `sbx-展示号序列` 实例在同一事务创建，MQ 消费登记 RUNNING，完成后写 EXITED、退出码和真实阶段、stdout/stderr 采样。
admin 通过 `JudgeInnerFeignClient` 请求判题节点终止；节点取消原始 `/run` HTTP future，阻止后续批次，
将实例置 KILLED，并将提交以 RE 结束，保留管理员原因。实例行锁使完成与终止串行裁决，避免收尾覆盖 KILLED。
取消不打断 Rabbit 消费线程，后续正常提交可以继续执行。

本机运行中进程退出时，Rabbit 重投的 RUNNING 实例会重新编译并记录 RECOVERED；同进程重复消息仍由句柄注册表拦截。
该恢复逻辑以当前**单判题 JVM**为前提。无本机执行句柄的历史 RUNNING 记录返回 409，不声称已回收资源；EXITED/KILLED 同样返回 409。
没有增加实时 CPU/运行内存采样；取消中请求的末尾输出无法在断开后补采。
`#85` 使用真实日志行首时间提供 `ts`，先按 `since` 筛选再取末尾 `lines` 行；旧无时间前缀的日志回退实例创建时间。

内部终止接口必须配置 `OJ_INNER_TOKEN`，空配置拒绝请求。admin、judge、teaching、ai 从同一 `.env.local` 读取；
模板只保留空占位，真实值不提交。旧 SQL 沙箱夹具改为 QUEUED，真实 RUNNING 终止由独立运行套件验证。
