### 1.3 统一响应包装、分页契约与 9 大标准错误码

*   **单对象响应包装：**
    ```json
    { "code": 200, "message": "ok", "data": { ... }, "traceId": "b7c9e2f1a4d3" }
    ```
    *规则：* `code` 与 HTTP 状态码严格同值；出错时 `data` 为 `null`；序列化保留 `null` 字段（不配置 `NON_NULL`），布尔值统一为 `true/false`，数据库 `snake_case` 自动映射为 JSON `camelCase`。
*   **分页响应包装与通用入参：**
    *   入参：`page`（默认 1）、`pageSize`（默认 20，上限 100）、`sortBy`（必须校验端点白名单防 SQL 注入）、`sortOrder`（`asc`/`desc`，默认 `desc`）、`kw`（模糊搜索）。
    *   响应：`data: { "list": [...], "total": 137, "page": 1, "pageSize": 20, "hasNext": true }`。
*   **全局 9 大标准错误码（严禁新增其他状态码）：**

|  code | 语义                | 典型触发场景                                                 | 前端处理规则                                   |
| ----: | ------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| `200` | 成功                | 正常业务返回                                                 | 解包 `data` 交由 `adapter` 转换                |
| `400` | 参数校验失败        | 缺必填项、枚举越界、`sortBy` 不在白名单、发布题目时测试点总分 ≠ 100 | 展示后端 `message`                             |
| `401` | 未登录或 Token 失效 | 无 Bearer 头、签名错、与 Redis `oj:auth:token:{uid}` 不匹配  | 清空本地 Token，跳转 `login.html?redirect=...` |
| `403` | 权限不足（含越权）  | 学生调 `/api/admin/**`、查看他人提交、考试模式调 AI 接口     | 停在当前页，`OJ.toast('没有权限执行该操作')`   |
| `404` | 资源不存在          | `problemId` / `submissionId` / `reportId` / `taskId` 不存在或已软删 | 渲染 `.state` 空态/错误态                      |
| `409` | 状态冲突            | 重复提交作业、已超 5 秒撤销窗口、对已结束考试交卷、乐观锁 `version` 冲突 | 提示刷新页面重试                               |
| `429` | 限流 / 防抖         | 3 秒内重复判题（`oj:judge:lock`）、AI 提示配额耗尽、SSE 并发超 2 条 | 禁用对应按钮，展示冷却或配额耗尽提示           |
| `500` | 服务内部错误        | 未捕获异常                                                   | 展示通用错误 + `traceId`                       |
| `502` | 上游依赖失败        | 云端与本地模型降级链全部失败、Go-Judge 沙箱返回非 200        | GET 请求指数退避重试 2 次                      |
| `504` | 上游超时            | 通道探活超时、AI 首字响应（TTFT）超 15s、判题超时            | 提示超时并允许手动重试                         |

### 2.1 七大核心字典标准（消除前后端硬冲突）

#### （1）判题状态字典（三字段联动下发：`status` + `statusCode` + `statusLabel`）

| ----------------: | ----------- | ------------------------ | ----------------------------------- | :------: |
|               `0` | `QUEUED`    | 排队中                   | `pending`                           |    否    |
|               `1` | `COMPILING` | 编译中                   | `pending`                           |    否    |
|               `2` | `JUDGING`   | 评测中                   | `pending`                           |    否    |
|               `3` | `AC`        | AC                       | `ac`                                |    是    |
|               `4` | `PAC`       | PAC                      | `pac`                               |    是    |
|               `5` | `WA`        | WA                       | `wa`                                |    是    |
|               `6` | `TLE`       | TLE                      | `tle`                               |    是    |
|               `7` | `MLE`       | MLE                      | `mle`                               |    是    |
|               `8` | `RE`        | RE                       | `re`                                |    是    |
|               `9` | `CE`        | CE                       | `ce`                                |    是    |

*注：未提交状态不入此枚举，由题目列表 `myStatus: null` 表达，前端映射为 `'none'`；沙箱实例状态独立为 `QUEUED / RUNNING / EXITED / KILLED`。*

#### （2）题目难度字典（5 档标准，对齐 `_SPEC.md:105` 与 `OJ.lvlName`）
*   `1` → `'入门'` ｜ `2` → `'简单'` ｜ `3` → `'中等'` ｜ `4` → `'较难'` ｜ `5` → `'困难'`。

#### （3）编程语言字典（消除 `C++ 17` 与 `C++17` 空格分裂）
*   `cpp` → `languageLabel: "C++ 17"`（时空限制倍率 `×1`）
*   `java` → `languageLabel: "Java 17"`（时空限制倍率 `×2`）
*   `python` → `languageLabel: "Python 3"`（时空限制倍率 `×2`）

#### （4）时间戳与时长规范（消除中文字符串排序 Bug）
*   所有时刻字段以 **`At`** 结尾，统一传输 **epoch 毫秒（`long`）**，如 `submittedAt: 1761302460000`、`dueAt: 1761388800000`。
*   所有耗时字段以 **`Ms`** 结尾，统一传输 **毫秒整数（`int`）**，如 `timeUsedMs: 92`、`ttftMs: 420`、`timeoutMs: 8000`。

#### （5）量纲与单位后缀规范（消除 1024× 与 1000× 换算事故）
*   **题目内存限制：** `memoryLimitMb`（单位：**MB**，如 `256`）。
*   **判题与沙箱实测内存：** `memoryUsedKb` / `memKb`（单位：**KB**，如 `4210`）。**字节（Go-Judge）↔ KB 的换算仅允许出现在 `oj-judge-service` 的 `JudgeAdapter` 类中**。
*   **调用成本：** `costCents`（单位：**人民币分**，整数，如 `21480` 对应前端展示 `'¥214.80'`）。
*   **比例与掌握度：** 统一为 `0–100` 数值（保留 1~2 位小数），如 `acRate: 68.4`、`masteryPercent: 82.0`（方向统一为**越高越强**）。

#### （6）实体主键与展示号（`display_no`）分离规范
DB 主键一律为 `BIGINT AUTO_INCREMENT`；对外展示号由服务端通过 Redis `INCR oj:seq:{biz}` 生成并写入 `display_no` 唯一列（前端严禁自行拼接）：
*   题目：`#1024`（直接由 `id` 拼 `#`）
*   提交：`S-20481`（`oj:seq:submission`）
*   作业：`A-0412`（`oj:seq:assignment`）
*   作业整份提交：`SA-0412-01`
*   查重报告：`P-0088`（`oj:seq:plagiarism`）
*   查重异步任务：`PL-0031`（`oj:seq:plagiarism_task`）
*   沙箱实例：`sbx-8841`（`oj:seq:sandbox`）

#### （7）AI 护栏双维枚举与其余核心枚举
*   **护栏动作 (`guardAction`)：** `0` 正常放行（`guardCode: "pass"`）｜ `1` 输入防注入阻断（`guardCode: "block"`）｜ `2` 输出流超 5 行代码块熔断改写（`guardCode: "rewrite"`）。
*   **护栏命中原因 (`guardReason`)：** `NONE` ｜ `LEAK_RATE`（答案泄漏）｜ `JAILBREAK`（越狱提示词注入）｜ `SENSITIVE_WORD`（敏感词）｜ `OVER_LENGTH_CODE`（超 5 行代码）。
*   **题目状态 (`prob_question.state`)：** `0` 草稿 ｜ `1` 已发布 ｜ `2` 已归档。
*   **教学活动模式 (`modeType`)：** `1` 平时练习 ｜ `2` 课后作业 ｜ `3` 期末考试。
*   **教学活动状态 (`teach_assignment.status`)：** `0` 草稿 ｜ `1` 未开始 ｜ `2` 进行中 ｜ `3` 已结束。
*   **通道健康状态 (`healthStatus`)：** `ON` ｜ `DEGRADE` ｜ `OFF` ｜ `PROBING`。

## 第 5 章：实时流通道（3 条 SSE）与异步沙箱引擎协议规范

### 5.1 三条 SSE 实时流通道协议规范
*   **通用约定：** 响应头固定为 `Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。每 15 秒发送 `: ping\n\n` 心跳帧。前端统一使用 `fetch + ReadableStream`（携带 `Authorization: Bearer` 头）或短期票据连接。
*   **通道 1：启发式 AI 对话流（`POST /api/ai/chat/stream` —— 共 6 种标准事件）**
    1. `event: router_step` $\rightarrow$ `{"stage":3, "stageName":"排错诊断", "hintLevel":2, "levelDesc":"逻辑拆解与边界反例", "routerModel":"Qwen2.5-Coder-7B"}`
    2. `event: tool_calling` $\rightarrow$ `{"toolName":"fetchFailedTestCaseTool", "summary":"已拉取首个失败测试点 #3 特征"}`
    3. `event: fallback_notice` $\rightarrow$ `{"fromChannel":"cloud-ds", "toChannel":"local-qwen", "msg":"云端响应超时，已无缝切换至本地模型"}`
    4. `event: token` $\rightarrow$ `{"delta":"请看你代码的第 8 行..."}`
    5. `event: guardrail_rewrite` $\rightarrow$ `{"reason":"检测到超过5行的可执行代码段", "replacementText":"..."}`
    6. `event: done` $\rightarrow$ `{"recordId":88123, "remainingQuota":1, "actualModelUsed":"Qwen2.5-Coder-7B"}`
*   **通道 2：考试实时监考事件流（`GET /api/teaching/exam/{examId}/events` —— 共 6 种事件）**
    *   支持 `Last-Event-ID: {seq}` 断点续传（数据源为 `exam_monitor_event` 表）：`snapshot`（初连快照）、`student`（考生状态变更）、`event`（切屏/交卷/离线单条事件）、`summary`（10s 定时汇总）、`resync`（历史过旧通知全量重拉）、`exam_end`（收卷广播）。
*   **通道 3：异步查重任务进度流（`GET /api/teaching/plagiarism/tasks/{taskId}/events` —— 共 4 种事件）**
    *   与轮询接口 `#68` 共享 Redis 快照 `oj:plagiarism:task:{taskId}`：`progress`（每 5% 或 2s 推送）、`pair`（发现高危疑似对实时推送）、`done`（完成）、`failed`（失败）。

### 5.2 Go-Judge 容器沙箱三步最小改造与 RabbitMQ 协议
*   **RabbitMQ 判题队列（不变）：** 交换机 `oj.judge.direct.exchange` $\rightarrow$ 队列 `oj.judge.submit.queue` $\rightarrow$ 路由键 `oj.judge.submit.key`。
*   **Go-Judge 可观测最小改造（支撑 `a-audit.html` 沙箱监控与强杀）：**
    1. `oj-judge-service` 发起 `POST http://localhost:5050/run` 前，先向 `judge_sandbox_instance` 插入 `RUNNING` 记录（生成 `sandbox_instance_id = "sbx-8841"`），并在 `/run` 请求体附带可选字段 `"instanceTag": "sbx-8841"`。
    2. Go-Judge 侧通过旁路接口 `GET /instances?state=running` 暴露实时 CPU/内存，通过 `POST /instances/{tag}/kill` 支持强制回收（返回 `exitCode = 137`）。
    3. `/run` 同步返回后，`oj-judge-service` 将实例更新为 `EXITED` 并写入 `finished_at` 与 `exit_code`。

(function (global) {
  'use strict';
  var WHITE = ['login.html', 'index.html'];
  var page = (location.pathname.split('/').pop() || 'index.html');

      return false;
    }
    return true;

  };
