## 1. 版本策略：向后兼容补全

契约 v2.0 **不是重写**，而是在 v1.0 基础上的**严格增量补全**：

| 允许 | 禁止 |
|---|---|
| 新增端点 | 修改 v1.0 已发布端点的路径、HTTP 方法 |
| 新增字段（响应/请求） | 重命名 v1.0 既有字段（如 `statusLabel` 不得改回 `statusText`） |
| 新增枚举值 | 改变 v1.0 既有枚举的数值含义（如 `status=3` 必须仍是 AC） |
| 新增表 / 新增列 | 删除 v1.0 既有表或列 |
| 新增 Redis Key | 改动 6 类既有 Key 的命名 |

**理由**：v1.0 的 9 个端点已被 PRD 验收条款（AC-1.1 ~ AC-3.2）与论文正文锚定，且 `prototype/workbench/VUE-MIGRATION.md` 等历史资产引用过它们。破坏性变更会让已写好的论文段落、答辩 PPT、旧迁移手册全部失效。

**已知的历史包袱（不作为兼容对象）**：`prototype/workbench/VUE-MIGRATION.md` 第 9 节（L946–L1098）对接的是**更早的 HEAD 版契约**，其中 `statusDesc` / `statusText` / `unlockedAiStages` / `highlightAiStage3` / `agent_step` / `clickedStageCapsule` / `currentEditorCode` / `guardrailTriggered` / `blurDurationSeconds` / `currentSwitchCount` / `isRedFlagged` / `warningMsg` 共 12 个字段名在现行文档中**一个都不存在**。该节作废，不得作为对接依据。

## 2. 服务划分与 URL 前缀

网关前缀固定 `http://localhost:8080/api/{service_module}/...`（v1.0 L209 已定）。

| 模块前缀 | 归属服务 | 职责 | 与原状差异 |
|---|---|---|---|
| `/api/auth/*` | `oj-teaching-service` | 登录、登出、续期、当前用户、菜单、改密 | **全新**（v1.0 只有 Redis Key，无端点） |
| `/api/problem/*` | `oj-problem-service` | 题库 CRUD、测试点 CRUD/批量、状态流转、导入、字典 | **全新**（v1.0 此服务只有内部 Feign） |
| `/api/judge/*` | `oj-judge-service` | 自测、提交、轮询、提交记录列表/详情/轨迹、样例运行 | v1.0 有 3 个，新增 4 个（统计内嵌，不单开） |
| `/api/ai/*` | `oj-ai-agent-service` | 工作台初始化、SSE 对话、会话历史、反馈、配额、通道 | v1.0 有 2 个，新增 4 个 |
| `/api/teaching/*` | `oj-teaching-service` | 作业、考试、学情、查重、班级、待办、通知 | v1.0 有 4 个，新增 **36** 个 |
| `/api/admin/*` | `oj-admin-service`（**新增第 5 个服务**） | 模型通道管理、AI 调用审计、沙箱运维、全站统计、健康聚合 | **全新**（v1.0 零覆盖，16 个端点） |

**为什么新增 `oj-admin-service`**：管理端需要「通道配置 + 调用审计 + 沙箱运维」三类聚合，跨 `oj-ai-agent-service`、`oj-judge-service` 两个域。塞进任何一个业务服务都会让该服务同时承担「在线业务」与「运维治理」两种变化速率不同的职责。独立出来后，它只做两件事：聚合查询 + 运维写操作，通过 OpenFeign 调其余 4 个服务。

## 3. 统一响应包装与分页

### 3.1 单对象响应

```json
{ "code": 200, "message": "ok", "data": { }, "traceId": "b7c9e2f1a4d3" }
```

- `code` 与 HTTP 状态码**同值**（不搞 200 包 500 的伪成功）。
- `data` 在出错时为 `null`。
- `traceId` 为链路追踪 ID，前端在错误提示里展示，便于答辩演示定位。

### 3.2 分页响应

```json
{ "code": 200, "message": "ok",
  "data": { "list": [], "total": 137, "page": 1, "pageSize": 20, "hasNext": true } }
```

### 3.3 分页/排序/筛选通用参数

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `page` | int | 1 | ≥1，从 1 起 |
| `pageSize` | int | 20 | 1~100，超过 100 按 100 处理 |
| `sortBy` | string | 端点规定 | 必须命中该端点的**排序字段白名单**，否则 400 |
| `sortOrder` | string | `desc` | `asc` / `desc` |
| `kw` | string | — | 关键词模糊匹配，服务端做 LIKE 或全文索引 |

**禁止**：把排序字段直接拼进 SQL（防注入），必须走白名单枚举映射。

### 3.4 错误码全集（v1.0 只有 4 个，v2.0 扩到 9 个）

| code | 含义 | 触发场景 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数校验失败 | 字段缺失、枚举越界、分页越界、排序字段不在白名单 |
| 401 | 未登录 / token 失效 | 无 `Authorization` 头、Redis `oj:auth:token:{userId}` 不存在或过期 |
| 403 | 权限不足 | 角色不符（学生访问 `/api/admin/*`）、越权访问他人资源（学生查别人提交） |
| 404 | 资源不存在 | `problemId` / `submissionId` / `reportId` 查不到 |
| 409 | 状态冲突 | 重复提交同一题（`oj:judge:lock` 未过期）、对已结束考试交卷、对已归档题目编辑 |
| 429 | 限流 / 防抖 | `oj:judge:lock:{userId}` 3 秒内重复提交、AI 配额耗尽、SSE 并发超限 |
| 500 | 服务内部错误 | 未捕获异常 |
| 502 | 上游依赖失败 | 模型通道不可用且降级链全部失败、Go-Judge 返回非 200 |
| 504 | 上游超时 | 通道探测超时、AI 首 token 超时 |

v1.0 只定义了 `200/400/401/403/429`，原型实际需要 `404`（题目被删）、`409`（重复交卷）、`502/504`（通道探测失败）—— 这是**必须补的**，否则前端无法区分「通道挂了」和「参数错了」。

## 4. 序列化约定

- **数据库**：`snake_case`
- **JSON**：`camelCase`（Jackson 需显式配置 `PropertyNamingStrategies.LOWER_CAMEL_CASE`，或每个字段加 `@JsonProperty`。**Spring Boot 默认就是 camelCase，无需额外配置**，但 DTO 字段名必须与 JSON 一致）
- **布尔**：`true`/`false`，禁用 `0/1`；DB 侧 TINYINT(1) 由 MyBatis `BooleanTypeHandler` 转换
- **null 字段**：**保留**（不配 `NON_NULL`），前端用 `=== null` 判断空态。这是刻意选择——原型大量使用「字段为 null 时显示空态文案」，过滤掉 null 会让前端无法区分「没这个字段」与「有字段但无值」
- **大整数**：`judge_submission.id` 等自增主键位数 ≤ 15 位，可安全以 JSON number 传输（JS `Number.MAX_SAFE_INTEGER` = 9007199254740991，16 位）。**若未来切换雪花 ID（19 位），必须改为字符串序列化**（`@JsonSerialize(using = ToStringSerializer.class)`），否则前端精度丢失。当前不切，但要在字段注释里写明这条约束。

## 5. 七类字典统一（核心中的核心）

### 5.1 判题状态 `submission.status`（int 为真值）

| int | 枚举名 | 展示标签 | 前端 CSS class | 终态 |
|---:|---|---|---|:--:|
| 0 | QUEUED | 排队中 | `pending` | ✗ |
| 1 | COMPILING | 编译中 | `pending` | ✗ |
| 2 | JUDGING | 评测中 | `pending` | ✗ |
| 3 | AC | AC | `ac` | ✓ |
| 4 | PAC | PAC | `pac` | ✓ |
| 5 | WA | WA | `wa` | ✓ |
| 6 | TLE | TLE | `tle` | ✓ |
| 7 | MLE | MLE | `mle` | ✓ |
| 8 | RE | RE | `re` | ✓ |
| 9 | CE | CE | `ce` | ✓ |

**契约新增 `statusCode` 字段**：`status`（int）是真值，`statusLabel`（大写缩写）供直接展示，`statusCode`（小写）供前端拼 CSS class。加这一个字段，原型 `OJ.statusTag(s)` 就能零改动继续用——它本来就是把入参直接当 class 名。

**以下两个不是判题状态，禁止混入 `submission.status`**：
- `none`（未提交）→ 由列表/详情接口返回 `myStatus: null` + `myScore: null` 表达，前端自己派生
- `run` / `idle`（沙箱实例状态）→ 属于沙箱域，见 5.6

### 5.2 难度 `difficulty`：3 档扩为 5 档

| 值 | 名称 | 说明 |
|---:|---|---|
| 1 | 入门 | 新增档位 |
| 2 | 简单 | 旧值 1 迁移至此 |
| 3 | 中等 | 旧值 2 迁移至此 |
| 4 | 较难 | 新增档位 |
| 5 | 困难 | 旧值 3 迁移至此 |

**决策理由**：`prototype/app/_SPEC.md:105` 已把 5 档定为**规范级硬约定**，全站 6 处引用（题库筛选、题库列表、工作台徽标、作业抽屉、学情表、考试题号列表），`?lvl=4/5` 深链已写在 `s-problems.html` 里。改前端意味着推翻已验收的视觉规范（第五轮整改成果），成本远高于扩一个 TINYINT 的取值域。

**迁移 SQL（两种等价写法，二选一）**：①单条原子 `UPDATE prob_question SET difficulty = CASE difficulty WHEN 1 THEN 2 WHEN 2 THEN 3 WHEN 3 THEN 5 END;`（CASE 表达式整体对原始值求值，天然无先后问题，**推荐**）；②若要拆成三条独立 UPDATE，**必须倒序**执行 `=5 WHERE =3` → `=3 WHERE =2` → `=2 WHERE =1`，正序会把刚被改成 2 的行再推到 3。落库脚本与回滚见 `02-契约补全规范-v2.0.md` §8.2。之后改列注释与默认值。

### 5.3 语言 `language`

| 存储/传输键 | 展示标签 | 时限倍率（PRD L63） |
|---|---|---:|
| `cpp` | `C++ 17` | ×1 |
| `java` | `Java 17` | ×2 |
| `python` | `Python 3` | ×2 |

原型内部对 C++ 的写法本身就不统一：`s-submissions.html:710` 是 `C++ 17`（带空格），`t-plagiarism.html` 是 `C++17`（不带空格）。统一由 `languageLabel` 字段输出，或前端用一张字典渲染，**禁止在业务代码里散写字面量**。

### 5.4 时间与时长

| 类别 | 约定 | 示例 |
|---|---|---|
| 时间点（响应） | **epoch 毫秒**（`long`），字段名以 `At` 结尾 | `dueAt: 1761310860000` |
| 时间点（请求） | 同上 | `startAt` / `endAt` |
| 时长 | **毫秒**（`int`），字段名以 `Ms` 结尾 | `timeUsedMs` / `ttftMs` |
| 日期展示 | 前端 `OJ.fmt.at()` 格式化为 `10-24 23:41` | — |

**关键改动**：契约 v1.0 的 `create_time DATETIME` 等字段是 DB 类型，接口层必须转换。原型 `shell.js` 的 `at: '10-24 23:41'` 与 `left: '2 天'` 都是**预格式化中文**，其中 `left` 还靠 `parseInt` 排序（跨月即错）—— v2.0 **不再传中文相对时间**，只传 `dueAt` 时间戳，`left` 由前端计算。这一条同时修掉了原型里一个真实 bug。

### 5.5 单位与量纲

| 域 | 单位 | 字段命名要求 |
|---|---|---|
| 判题内存 | **KB** | `memoryKb` / `memoryUsed`（v1.0 遗留名，注释写明 KB） |
| 题目内存配置 | **MB** | `memoryLimitMb` |
| 时间/耗时 | **毫秒** | `timeUsedMs` / `ttftMs` / `stage1CostMs` |
| 沙箱内存 | **KB** | `memoryKb` |
| 成本 | **分**（整数） | `costCents` |
| Token | 个（整数） | `promptTokens` / `completionTokens` / `totalTokens` |
| 相似度 | 0–100，2 位小数 | `stage1AlgoSim` / `stage2AiSim` |
| 百分比 | 0–100（**不是 0–1**） | `acceptance` / `progress` |
| 分值 | 整数 0–100 | `score` / `maxScore` / `fullScore` |

**规则**：新增字段一律自带单位后缀。v1.0 遗留的 `memoryUsed` / `timeUsed` / `memoryKb` 不重命名（兼容），但在文档里逐条注明单位。

**已知三方冲突**（必须在 v2.0 消除）：
- `ai_model_config.timeout_seconds`（秒）vs 原型 `CFG.timeout = 8000`（毫秒）→ 统一为 `timeoutMs`，DB 列改名 `timeout_ms`
- 沙箱 `mem = 51200`（KB，原型显示 `50.0 MB`）vs Go-Judge `memoryLimit = 268435456`（字节）→ 接口层统一 KB，**换算只发生在 `oj-judge-service` 调 Go-Judge 的适配层**，且必须有单测

### 5.6 其余枚举

| 域 | 取值 |
|---|---|
| `role` | `STUDENT` / `TEACHER` / `ADMIN`（v1.0 已定，保持） |
| `assignment.modeType` | `1` 练习 / `2` 作业 / `3` 考试（v1.0 已定） |
| `assignment.status`（**新增**） | `0` 草稿 / `1` 未开始 / `2` 进行中 / `3` 已结束 |
| `question.state`（**新增**） | `0` 草稿 / `1` 已发布 / `2` 已归档 |
| `sandbox.state` | `QUEUED` / `RUNNING` / `EXITED` / `KILLED` |
| `plagiarism.auditStatus` | `0` 待审 / `1` 确认抄袭 / `2` 排除（v1.0 已定） |
| `plagiarism.taskState`（**新增**） | `PENDING` / `STAGE1` / `STAGE2` / `DONE` / `FAILED` |
| `ai.stage` | `1` 题意澄清 / `2` 思路启发 / `3` 错因诊断 / `4` 复杂度优化（v1.0 `stage_type` 1–4） |
| `ai.hintLevel` | `1`–`3`（v1.0 已定） |
| `guard.action` | `0` 通过 / `1` 输入侧拦截 / `2` 输出侧改写（v1.0 已定） |

**`guard.action` 与 `guard.reason` 必须并存**：v1.0 只有单值 action，无法回答「泄漏率/越狱特征/敏感词各命中多少次」，而 `a-audit.html` 的 `hitDist` 三个数字正是这三个原因。这是**把一维动作拆成「动作 + 原因」两维**，而不是改枚举语义。

## 6. ID 策略：主键不出现在 UI

| 实体 | 主键 | 展示号 | 生成规则 |
|---|---|---|---|
| 题目 | `prob_question.id` BIGINT（≥1001） | `#1024` | 前端拼 `'#' + id` |
| 提交 | `judge_submission.id` BIGINT | `S-20481` | 新增 `display_no`，Redis `oj:seq:submission` INCR → `'S-' + n` |
| 作业 | `teach_assignment.id` BIGINT | `A-0412` | 新增 `display_no`，`'A-' + n` |
| 查重报告 | `teach_plagiarism_report.id` BIGINT | `P-0088` | 新增 `display_no`，`'P-' + n` |
| 沙箱实例 | `judge_sandbox_instance.id` | `sbx-8841` | 新增 `display_no`，`'sbx-' + n` |

**理由**：原型里 `S-` / `P-` / `A-` / `sbx-` 前缀承载了**类型辨识功能**（用户一眼知道是提交还是题目），直接丢掉会降低可读性；但主键带前缀又会污染索引与自增。用独立的 `display_no`（`VARCHAR(16)` + 唯一索引）两全。

`display_no` 一律由**服务端生成**，前端不得自行拼接——否则并发下会撞号。

## 8. 状态机

```
submission:  0 QUEUED → 1 COMPILING → 2 JUDGING → ┬→ 3 AC
                                                  ├→ 4 PAC
                                                  ├→ 5 WA
                                                  ├→ 6 TLE
                                                  ├→ 7 MLE
                                                  ├→ 8 RE
                                                  └→ 9 CE
              （1 可直接跳到 9 CE；任何状态都不得回退）

assignment:  0 草稿 → 1 未开始 → 2 进行中 → 3 已结束
              （1→2 由 start_time 到达触发，2→3 由 end_time 到达或教师手动结束触发）

question:    0 草稿 → 1 已发布 → 2 已归档
              （2 可回到 1；0→1 需校验测试点总分 = 100）

sandbox:     QUEUED → RUNNING → ┬→ EXITED（正常结束）
                                └→ KILLED（被终止）
              RUNNING 超时 → EXITED（exitCode=124 表示 clockLimit 超时）

plagiarism:  PENDING → STAGE1 → STAGE2 → DONE
                              └→ FAILED（阶段 1 无有效样本）
```

## 10. 缺口判定口径（A/B/C/D/E）

三份盘点报告（`raw/student.md`、`raw/teacher.md`、`raw/admin-global.md`）使用同一套五级判定，词汇必须一致：

| 判定 | 全称 | 含义 | 修复动作 |
|---|---|---|---|
| **A** | 现有接口直接覆盖 | 字段在当前 9 个端点的响应里已有同名/同义字段 | 前端直接对接 |
| **B** | 现有表可派生但无接口 | 9 张表里有字段，但没有查询端点 | 新增端点（写 SELECT） |
| **C** | 现有表缺字段 | 表存在，但缺列/缺精度/缺单位 | `ALTER TABLE` 加列 |
| **D** | 无任何表落点 | 连表都没有 | 新增表 |
| **E** | 纯前端派生 | 可由已有数据算出（合计、占比、排序、倒计时） | 前端计算，无需后端 |

**注意 A 类的判定必须严格**：字段名不同但语义相同也算 A（如 `statusLabel` 覆盖原型的 `statusName(s)` 输出）。语义不同则降为 B 或 C。

## 11. 汇总口径（三份盘点结果，供交叉引用）

| 范围 | 条目数 | A | B | C | D | E |
|---|---:|---:|---:|---:|---:|---:|
| 学生端（`raw/student.md`） | 206 | 27 | 110 | 23 | 23 | 23 |
| 教师端（`raw/teacher.md`） | 176 | 13 | 73 | 39 | 30 | 21 |
| 管理端 + 门户 + 全站框架（`raw/admin-global.md`） | 110 | 0 | 42 | 28 | 23 | 17 |
| **合计** | **492** | **40** | **225** | **90** | **76** | **61** |
| **占比** | 100% | **8.1%** | **45.7%** | **18.3%** | **15.4%** | **12.4%** |

**读法**：A 类 8.1% 是「今天就能跑」的部分；B 类 45.7% 是「表够、缺接口」——这是工作量主体但风险最低；C+D 合计 33.7% 是「必须改数据模型」；E 类 12.4% 不占后端工时。

**契约侧存量**：9 个 HTTP 端点（8 个小节，3.3 节含 GET+PUT 两个方法）、9 张 MySQL 表、6 类 Redis Key、4 个 OpenFeign 客户端、1 组 RabbitMQ 交换机/队列/路由键、1 个 Go-Judge 同步协议。
