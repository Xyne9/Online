## 1. 改造总原则

### 1.1 三条不变量

| # | 不变量 | 精确边界 | 怎么证明没破 |
|---|---|---|---|
| 1 | **DOM 结构一行不动** | 16 页元素层级、顺序、`x-show`/`x-for` 容器位置，以及 `<body>` 上的 `data-role`/`data-page`/`data-crumb` | 同数据下改造前后截图逐像素比对，差异必须为 0 |
| 2 | **class 名一行不动** | `styles/components.css`、`styles/pages.css`、`styles/shell.css` 已定义的类不得增删改名，也不得为满足新需求另造类名 | `grep -o 'class="[^"]*"' 页 \| sort` 改造前后集合相等 |
| 3 | **设计 token 一行不动** | `styles/tokens.css` 全文 + `_SPEC.md` 12 条硬规则（6 级字号、颜色只取 token、强调色 ≤10%、四态、状态切换不改尺寸、不用 emoji、数字右对齐 tabular-nums、必须写空态…） | `git diff prototype/app/styles/tokens.css` 为空 |

唯一允许新增的 HTML 是页尾的 `<script src>`，以及 `x-data` 对象内部新增属性。**新增任何 `<div>`、任何 `class` 都算破红线。** 允许新增的**文件**只有：`api/**`、`adapter/**`、`boot.js`、`login.html`（第 17 页，见 §6.1）。16 页里唯一的特例是门户 `index.html`——它全文 416 行、`<script` 命中 0、没有 Alpine，改造方式见 §4 第一行。

### 1.2 总策略：常量 → 异步状态，不重写模板

16 个文件里 `fetch(` / `XMLHttpRequest` / `EventSource` / `WebSocket` 命中数**全部为 0**。数据只有两个来源：`shell.js:320-454` 的 8 组内存常量，或页面内 `const`（`s-analytics.html:676` 的 `DAYS`、`t-analytics.html:704` 的 `KP_BASE`、`t-monitor.html:509-512` 的 38 人名补丁）。所有"异步"都是 `setTimeout`。

所以对接不是"改几行取值"，而是**同一个表达式换一种求值时机**：

```js
// 改造前：同步常量，模板直接读
list: OJ.problems,
get filtered() { return this.list.filter(function (p) { return p.status === this.status; }); },

// 改造后：异步状态。模板一个字不改，只是 list 的初值变成 []
list: [], loading: true, err: '',
async init() {
  if (api.http.useMock()) return this.loadMock();          // ← 第一行，否则演示时页面全空
  try {
    var d = await api.problem.list({ page: this.page, pageSize: this.pageSize });
    this.list = d.list.map(adapter.adaptProblem);          // ← 映射在这里，不在模板里
    this.total = d.total;
  } catch (e) { this.err = api.http.describe(e); }
  finally { this.loading = false; }
},
```

两条硬规矩：

1. **映射只发生在赋值那一刻**（`adapter.adaptX`）。模板里禁止出现 `.toLowerCase()`、`* 1024`、`new Date()`、`parseInt('2 天')`。同一字段被 3~5 个页面消费，散在模板里的换算等于把口径写死 5 遍。
2. **四态必须补齐**：`loading` / `err` / 空态 `/` 有数据。`_SPEC.md:298` 要求"必须写空态"，现有 10 页有 `loadErr`，`s-analytics`、`s-workbench`、`t-dashboard`、`t-monitor`、`t-plagiarism`、`index` 六处没有——接真实接口后这六处会白屏。

### 1.3 为什么是 Alpine 原地改造，不是迁 Vue

`prototype/workbench/VUE-MIGRATION.md` 第 9 节（L946–L1098）对接的是更早 HEAD 版契约，其中 `statusDesc`/`statusText`/`unlockedAiStages`/`highlightAiStage3`/`agent_step`/`clickedStageCapsule`/`currentEditorCode`/`guardrailTriggered`/`blurDurationSeconds`/`currentSwitchCount`/`isRedFlagged`/`warningMsg` 十二个字段名**在现行契约里一个都不存在**，该节已作废；且该文档只覆盖 `prototype/workbench/` 一个页面。

| 维度 | 迁 Vue（旧方案） | Alpine 原地改造（本方案） |
|---|---|---|
| 工具链 | 需 npm + Vite + Pinia + Monaco，与"双击 html 即可打开"的交付形态正面冲突 | 零构建，`vendor/alpine.min.js` 已在仓库（`_SPEC.md` 标注 🔒） |
| 覆盖率 | 1 页 | 16 页 |
| 视觉资产 | `.tag/.card/.tbl/.pager` 需整体重写为 Element Plus | 一行 class 都不动，`8ec9fda` 第五轮视觉零损失 |
| 并行度 | 组件树重构，只能串行 | 每页一个 `x-data` 对象，可 4 人并行，页间零冲突 |
| 演示连续性 | 改到一半无法演示 | `?mock=1` 保证任何阶段都能跑完整演示（§2.4） |

结论：`VUE-MIGRATION.md` 作为历史资产保留，不再作为实施依据；本指南是唯一执行口径。

按 `00-基线决策.md` §2 的 6 个 URL 前缀切分，一个前缀一个文件——职责边界与服务边界一致。**加载顺序固定，四个新增文件必须插在原有的 `shell.js` 与 `vendor/alpine.min.js` 之间**（以 `s-problems.html:420-421` 原有的两行为基线）：

```html

<script src="api/http.js"></script>
<script src="api/sse.js"></script>
<script src="adapter/index.js"></script>
<script src="boot.js"></script>
```

`_SPEC.md` 规定 `shell.js` **不能加 defer**、`vendor/alpine.min.js` **必须 defer 且排在 `shell.js` 之后**，所以新增文件一律插在两者之间、同样不带 defer，保证 Alpine 启动时 `api`/`adapter` 已就绪。

### 2.2 `api/http.js`：统一请求封装

```js
/* api/http.js —— 无构建工具，挂 window.api.http */
(function (global) {
  'use strict';
  var BASE = '';                       // 同源留空；直连网关改 'http://localhost:8080'
  var TOKEN_KEY = 'OJ_TOKEN', MOCK_KEY = 'OJ_USE_MOCK', TRACE_HEAD = 'X-Trace-Id';
  var TIMEOUT = 15000;

  function ApiError(code, message, traceId, data) {
    var e = new Error(message || '请求失败');
    e.name = 'ApiError'; e.code = code; e.traceId = traceId; e.data = data;
    return e;
  }
  function useMock() {
    if (/[?&]mock=(1|true)\b/.test(String(location.search || ''))) return true;
    try { return localStorage.getItem(MOCK_KEY) === '1' || sessionStorage.getItem(MOCK_KEY) === '1'; }
    catch (e) { return false; }
  }
  function getToken() { try { return localStorage.getItem(TOKEN_KEY) || ''; } catch (e) { return ''; } }
  function setToken(t) {
    try { t ? localStorage.setItem(TOKEN_KEY, t) : localStorage.removeItem(TOKEN_KEY); } catch (e) {}
  }
  function newTraceId() { return 'web-' + Date.now().toString(36) + '-' + Math.random().toString(36).slice(2, 8); }
  function buildQuery(q) {
    if (!q) return '';
    var out = [];
    Object.keys(q).forEach(function (k) {
      var v = q[k];
      if (v === null || v === undefined || v === '') return;
      (Array.isArray(v) ? v : [v]).forEach(function (x) {
        out.push(encodeURIComponent(k) + '=' + encodeURIComponent(x));
      });
    });
    return out.length ? '?' + out.join('&') : '';
  }

  var MESSAGES = {
    400: '请求参数不合法', 401: '登录已过期，请重新登录', 403: '没有权限执行该操作',
    404: '数据不存在或已被删除', 409: '数据状态已变化，请刷新后重试',
    429: '操作太频繁，请稍候再试', 500: '服务器内部错误',
    502: '网关错误：下游服务不可用', 504: '请求超时'
  };

  function toLogin() {
    if ((location.pathname.split('/').pop() || '') === 'login.html') return;   // 防死循环
    location.replace('login.html?redirect=' + encodeURIComponent(location.pathname + location.search));
  }
  function describe(err) {
    if (!err) return '未知错误';
    var msg = err.message || MESSAGES[err.code] || '请求失败';
    return err.traceId ? msg + '（traceId: ' + err.traceId + '）' : msg;
  }
  function delay(ms) { return new Promise(function (r) { setTimeout(r, ms); }); }

  function once(method, path, opts) {
    opts = opts || {};
    var ctrl = new AbortController();
    var timer = setTimeout(function () { ctrl.abort(); }, opts.timeoutMs || TIMEOUT);
    var tid = newTraceId();
    var headers = Object.assign({}, opts.headers || {}, { 'X-Trace-Id': tid });
    var token = getToken();
    if (token) headers.Authorization = 'Bearer ' + token;      // credentials 用 omit，Bearer 与 Cookie 不混用
    var body = opts.body;
    if (body instanceof FormData) { delete headers['Content-Type']; }
    else if (body !== undefined) { headers['Content-Type'] = 'application/json;charset=UTF-8'; body = JSON.stringify(body); }

    return fetch(BASE + path + buildQuery(opts.query), {
      method: method, headers: headers, body: body, credentials: 'omit', signal: ctrl.signal
    }).then(function (res) {
      clearTimeout(timer);
      if (opts.raw) return res;                                  // 导出 CSV 等场景
      if (res.status === 401) { setToken(''); toLogin(); throw ApiError(401, MESSAGES[401], tid); }
      return res.json().catch(function () { throw ApiError(res.status, '响应不是合法 JSON', tid); })
        .then(function (env) {
          if (env && env.code !== undefined && env.code !== 200) {
            if (env.code === 401) { setToken(''); toLogin(); }
            throw ApiError(env.code, env.message || MESSAGES[env.code], env.traceId || tid, env.data);
          }
          return env && env.data !== undefined ? env.data : env;
        });
    }, function (err) {
      clearTimeout(timer);
      if (err && err.name === 'AbortError') {
        throw ApiError(504, '请求超时（' + ((opts.timeoutMs || TIMEOUT) / 1000) + 's）', tid);
      }
      throw ApiError(0, '网络不可达：请确认网关已启动，或用 ?mock=1 演示', tid);
    });
  }

  function request(method, path, opts) {
    opts = opts || {};
    if (useMock()) {                                             // MOCK 短路，不产生真实请求
      if (!global.OJMock) return Promise.reject(ApiError(500, 'api/mock.js 未加载'));
      return global.OJMock.request(method, path, opts)
        .then(function (d) { return new Promise(function (r) { setTimeout(function () { r(d); }, 180); }); });
    }
    var maxRetry = opts.retries !== undefined ? opts.retries : (method === 'GET' ? 2 : 0);
    var attempt = 0;
    function fire() {
      return once(method, path, opts).catch(function (e) {
        var retriable = (e.code === 502 || e.code === 504 || e.code === 0);
        if (attempt < maxRetry && retriable) {
          attempt += 1;
          return delay(400 * Math.pow(2, attempt - 1)).then(fire);   // 400ms → 800ms
        }
        throw e;
      });
    }
    return fire();
  }

  global.api = global.api || {};
  global.api.http = {
    ApiError: ApiError, request: request,
    get: function (p, o) { return request('GET', p, o); },
    post: function (p, b, o) { return request('POST', p, Object.assign({ body: b }, o)); },
    put: function (p, b, o) { return request('PUT', p, Object.assign({ body: b }, o)); },
    del: function (p, o) { return request('DELETE', p, o); },
    token: { get: getToken, set: setToken },
    useMock: useMock, setMock: function (on) {
      try { on ? localStorage.setItem(MOCK_KEY, '1') : localStorage.removeItem(MOCK_KEY); } catch (e) {}
    },
    describe: describe, buildQuery: buildQuery
  };
})(window);
```

| 能力 | 落在哪 | 为什么这么定 |
|---|---|---|
| baseURL | `BASE` 常量，同源部署留空走反向代理 | 网关为 `http://localhost:8080/api/{module}/...`，同源可省掉 CORS 与预检 |
| 鉴权 | `Authorization: Bearer <token>` + `credentials:'omit'` | 与 §2.3 的 SSE 必须能带同一个头；Cookie 方案会让 `EventSource` 之外的 fetch 也要开 `withCredentials`，链路不统一 |
| 链路追踪 | 每请求生成 `X-Trace-Id`，异常时回显在文案里 | 响应包装含 `traceId`，用户截图报障时能直接定位 |
| 错误码 | 9 个业务码 + `0`（网络不可达），`code` 与 HTTP 同值 | `00-基线决策.md` §4 |
| 401 | 清 token + `location.replace('login.html?redirect=...')`，login 页自身不跳 | §6.1 |
| 超时 | `AbortController` + 15s，超时抛 `504` | 网关 504 语义一致，用户看到的文案统一 |
| 重试 | 仅 GET，默认 2 次，指数退避 `400×2ⁿ`，只重 502/504/0 | POST 提交判题绝不重试，否则会产生重复提交 |

### 2.3 `api/sse.js`：必须用 fetch + ReadableStream

**为什么不能用 `EventSource`**：① 它无法设置请求头，`Authorization: Bearer` 带不上去；② 只能 GET，而 `POST /api/ai/chat/stream` 要把 `userMessage`/`currentCode` 放进 body；③ 无法用 `AbortController` 取消，切题后旧流会继续往旧气泡里吐字；④ 无法区分 HTTP 错误码，`429` 配额耗尽会被当成一次普通断线自动重连，越重连越耗额度。

```js
/* api/sse.js —— fetch + response.body.getReader() + TextDecoder */
(function (global) {
  'use strict';

  function SSEClient(url, opts) {
    this.url = url; this.opts = opts || {};
    this.ctrl = new AbortController();
    this.closed = false; this.handlers = {}; this.buf = ''; this.frames = 0;
  }
  SSEClient.prototype.on = function (name, fn) { this.handlers[name] = fn; return this; };
  SSEClient.prototype.emit = function (name, payload, raw) {
    var fn = this.handlers[name] || this.handlers['*'];
    if (fn) { try { fn(payload, raw); } catch (e) { console.error('[sse]', name, e); } }
  };

  /* 帧格式：event: token / data: {...} / 空行结束；':' 开头是心跳注释；data 可多行 */
  SSEClient.prototype.parse = function (chunk) {
    var self = this, idx;
    this.buf += chunk;
    while ((idx = this.buf.indexOf('\n\n')) !== -1) {
      var block = this.buf.slice(0, idx);
      this.buf = this.buf.slice(idx + 2);
      var ev = 'message', data = [];
      block.split('\n').forEach(function (line) {
        if (!line || line.charAt(0) === ':') return;
        var p = line.indexOf(':');
        var field = p === -1 ? line : line.slice(0, p);
        var value = p === -1 ? '' : line.slice(p + 1).replace(/^ /, '');
        if (field === 'event') ev = value;
        else if (field === 'data') data.push(value);
      });
      if (!data.length) continue;
      var text = data.join('\n');
      if (text === '[DONE]') { self.close(); return; }
      var payload;
      try { payload = JSON.parse(text); } catch (e) { payload = { raw: text }; }
      self.frames++;
      if (self.opts.onFrame) self.opts.onFrame(ev, payload);
      self.emit(ev, payload, text);
    }
  };

  SSEClient.prototype.start = function () {
    var self = this;
    var headers = { 'Content-Type': 'application/json;charset=UTF-8', 'Accept': 'text/event-stream' };
    var tk = global.api.http.token.get();
    if (tk) headers.Authorization = 'Bearer ' + tk;
    headers['X-Trace-Id'] = 'web-' + Date.now().toString(36) + '-' + Math.random().toString(36).slice(2, 8);
    this.buf = '';
    this.frames = 0;                                        // 每次（重）连都重置首字计数
    this.ctrl = new AbortController();                       // 重连必须换一个新的 controller

    var guard = setTimeout(function () {                    // 首字超时：模型侧卡死时给用户一个交代
      if (self.frames === 0 && !self.closed) { self.emit('error', { code: 504, message: '模型首字超时' }); self.close(); }
    }, this.opts.firstTokenTimeoutMs || 15000);

    return fetch(this.url, {
      method: 'POST', headers: headers, credentials: 'omit',
      body: JSON.stringify(this.opts.body || {}), signal: this.ctrl.signal
    }).then(function (res) {
      if (res.status === 401) { global.api.http.token.set(''); location.replace('login.html'); throw new Error('401'); }
      if (!res.ok) {
        return res.text().then(function (t) {
          var env = {}; try { env = JSON.parse(t); } catch (e) {}
          var err = new Error(env.message || ('SSE HTTP ' + res.status));
          err.code = env.code || res.status; err.data = env.data; throw err;
        });
      }
      if (!res.body || !res.body.getReader) throw new Error('当前浏览器不支持 ReadableStream');
      var reader = res.body.getReader();
      var decoder = new TextDecoder('utf-8');
      function pump() {
        return reader.read().then(function (r) {
          if (r.done) { clearTimeout(guard); self.emit('end', {}); return; }
          clearTimeout(guard);
          self.parse(decoder.decode(r.value, { stream: true }));   // stream:true 处理跨 chunk 的多字节字符
          return pump();
        });
      }
      return pump();
    }).catch(function (e) {
      clearTimeout(guard);
      if (self.closed || e.name === 'AbortError') return;
      self.emit('error', { code: e.code || 0, message: e.message, data: e.data });
      if (self.opts.reconnect !== false) self.retry(e);
    });
  };

  SSEClient.prototype.retry = function (cause) {
    var self = this;
    if (cause && (cause.code === 429 || cause.code === 403 || cause.code === 401)) return;   // 不可重试
    this.tries = (this.tries || 0) + 1;
    if (this.tries > (this.opts.maxRetries === undefined ? 2 : this.opts.maxRetries)) {
      this.emit('fatal', { message: '连接失败，请稍后重试' }); return;
    }
    var wait = 800 * Math.pow(2, this.tries - 1);
    this.emit('reconnecting', { inMs: wait, attempt: this.tries });
    this.timer = setTimeout(function () { if (!self.closed) self.start(); }, wait);
  };

  SSEClient.prototype.close = function () {
    this.closed = true;
    clearTimeout(this.timer);
    try { this.ctrl.abort(); } catch (e) {}
  };

  global.api = global.api || {};
  global.api.sse = function (url, opts) {
    var c = new SSEClient(url, opts);
    c.start();
    return c;
  };
})(window);
```

### 2.5 `api/poll.js`：判题进度轮询

判题是唯一必须轮询的链路（0.5–10s 一次的短周期状态查询用 `GET` 比 SSE 省得多）。四条硬要求：**1s 一次、指数退避、页面隐藏暂停、终态自停**。

```js
/* api/poll.js —— 自适应轮询器 */
(function (global) {
  'use strict';

  function Poller(task, opts) {
    opts = opts || {};
    this.task = task;
    this.interval = opts.interval || 1000;      // 起始 1s
    this.max = opts.max || 5000;                // 退避上限
    this.limit = opts.limit || 120;             // 最多 120 次 ≈ 2 分钟
    this.isDone = opts.isDone || function () { return false; };
    this.onData = opts.onData || function () {};
    this.onError = opts.onError || function () {};
    this.onStop = opts.onStop || function () {};
    this.n = 0; this.timer = null; this.stopped = false; this.hidden = false;
  }

  Poller.prototype.start = function () {
    var self = this;
    this.stopped = false;
    this.n = 0;                                            // 重新 start 视为新一轮，重置计数
    if (!this._bound) {
      this._bound = true;
      this._onVis = function () {
        self.hidden = document.hidden;
        if (self.hidden) self.clear();                     // 页面隐藏立即停表
        else if (!self.stopped) { self.n = 0; self.tick(); }   // 回到前台补齐并重新计次
      };
      document.addEventListener('visibilitychange', this._onVis);
    }
    this.tick();
    return this;
  };

  Poller.prototype.clear = function () { clearTimeout(this.timer); this.timer = null; };

  Poller.prototype.tick = function () {
    var self = this;
    if (this.stopped || this.hidden) return;
    this.n += 1;
    this.task().then(function (data) {
      if (self.stopped) return;
      self.onData(data);
      if (self.isDone(data)) { self.stop('done'); return; }
      self.schedule(self.interval);                        // 有响应就回到 1s
    }).catch(function (e) {
      if (self.stopped) return;
      self.onError(e);
      if (e.code === 401 || e.code === 403 || e.code === 404) { self.stop('fatal'); return; }
      self.schedule(Math.min(self.max, self.interval * Math.pow(2, Math.min(self.n, 3))));
    });
  };

  Poller.prototype.schedule = function (ms) {
    var self = this;
    this.clear();
    if (this.n >= this.limit) { this.stop('limit'); return; }
    this.timer = setTimeout(function () { self.tick(); }, ms);
  };

  Poller.prototype.stop = function (why) {
    if (this.stopped) return;
    this.stopped = true;
    this.clear();
    if (this._bound) document.removeEventListener('visibilitychange', this._onVis);
    this.onStop(why);
  };

  global.api.poll = function (task, opts) { return new Poller(task, opts); };
})(window);
```

工作台提交后的用法：

```js

  isDone: function (s) { return s.status >= 3; },        // 3–9 为终态
  onData: function (s) { self.applyJudge(s); },          // 逐点点亮 + 落分数
  onError: function (e) { self.judgeErr = api.http.describe(e); },
  onStop: function (why) {
    self.judging = false;
    if (why === 'limit') self.judgeErr = '判题超时，请到提交记录查看';
  }
}).start();
```

`stop()` 的四个触发点：终态（`status>=3`）、次数上限、401/403/404、组件销毁（`destroy()` 里 `this.poller && this.poller.stop('dispose')`）。**不允许用 `setInterval`**——上一次请求没返回时会堆积，判题响应本身 500–1000ms 不确定，堆积后会把网关打出一串 429。

## 3. adapter 字段适配层

### 3.1 为什么必须有这一层

原型是"给人看的样子"，契约是"给机器传的数据"，两者在 7 个维度上口径不同（详细冲突清单见 `01-对接可行性判定报告.md` §3 的九类硬冲突）。适配层是**唯一允许做换算的地方**：页面拿到 adapter 的输出后，模板表达式可以直接用；反过来说，任何页面里出现换算就是在绕开这一层，必须打回。

| 冲突 | 后端 | 前端原型 | 后果（不修的话） |
|---|---|---|---|
| 判题状态 | `status` 0–9 整型 | 小写字符串 `ac`/`wa`… | `OJ.statusTag(3)` 拼出 `class="tag 3"`，`.tag.ac` 全不命中，全站状态标签裸奔 |
| 难度 | 1–5 | 页面里 1–4 混用 | 难度格数错位 |
| 语言 | `cpp`/`java`/`python` | `C++ 17` 与 `C++17` 两种写法并存 | 筛选器选不中、配色表 key 对不上 |
| 时间 | epoch ms | `'10-24 23:41'` 字符串 | `parseInt('2 天')` 得 `NaN`，排序失效 |
| 单位 | KB / 字节 / 分 / 0–100 | 混着写死 | 内存显示 1024 倍错、金额错 |

### 3.2 七张映射表

**① 判题状态：`status`(int) + `statusCode` + `statusLabel` 三字段怎么喂 `OJ.statusTag`**

关键事实：`shell.js:467-469` 的 `statusTag(s, extra)` 是 `'<span class="tag ' + s + ...`——**把入参直接当 CSS class 用**。传 `3` 会得到 `.tag 3`，`components.css` 里没有这个类，标签只剩裸文字。所以模板里**永远传 `statusCode`，绝不传 `status`**。

**④ 时间：epoch ms 与相对时间**

契约规定所有时刻字段以 `At` 结尾、epoch 毫秒（`dueAt: 1761310860000`），所有时长字段以 `Ms` 结尾（`timeUsedMs` / `ttftMs`）。原型是 `'10-24 23:41'` 与 `'2 天'` 两种字符串。**`OJ.fmt.at` 目前并不存在**——`shell.js` 只有 `fmt`（`:509`，千分位缩写），`00-基线决策.md` 里写的 `OJ.fmt.at()` 是待新增能力，别去调一个不存在的函数。

```js

function p2(n) { return n < 10 ? '0' + n : String(n); }

// 列表里的紧凑展示：10-24 23:41（跨年才补年份）
function fmtDateTime(ms) {
  if (!ms) return '—';
  var d = new Date(ms), now = new Date();
  var head = d.getFullYear() === now.getFullYear() ? p2(d.getMonth() + 1) + '-' + p2(d.getDate())
                                                   : d.getFullYear() + '-' + p2(d.getMonth() + 1) + '-' + p2(d.getDate());
  return head + ' ' + p2(d.getHours()) + ':' + p2(d.getMinutes());
}

// 倒计时/剩余时间：'2 天' / '3 小时' / '12 分钟' / '已结束'
function leftText(dueAt, now) {
  if (!dueAt) return '—';
  var gap = dueAt - (now || Date.now());
  if (gap <= 0) return '已结束';
  var day = Math.floor(gap / 86400000);
  if (day >= 1) return day + ' 天';
  var hour = Math.floor(gap / 3600000);
  if (hour >= 1) return hour + ' 小时';
  return Math.max(1, Math.floor(gap / 60000)) + ' 分钟';
}

// 时长：12ms / 1.2s / 1m03s
```

```js
/* adapter/page.js */
function paginate(list, q) {                       // MOCK 侧复用同一个语义
  var page = Math.max(1, Number(q && q.page) || 1);
  var size = Math.min(100, Math.max(1, Number(q && q.pageSize) || 20));
  var from = (page - 1) * size;
  var slice = list.slice(from, from + size);
  return { list: slice, total: list.length, page: page, pageSize: size, hasNext: from + slice.length < list.length };
}
// 页面侧统一派生，模板里不写算术
function pagerOf(res) {
  var pages = Math.max(1, Math.ceil(res.total / res.pageSize));
  return { page: res.page, pageSize: res.pageSize, total: res.total, pages: pages,
           hasPrev: res.page > 1, hasNext: !!res.hasNext };
}

(global.adapter = global.adapter || {}).page = { paginate: paginate, pagerOf: pagerOf };
```

## 5. 三处必须删除的伪造逻辑

这三处不是"实现得糙"，而是**讲了一个系统里不存在的故事**。评审只要追问一句"这个数据哪来的"就穿帮，且它们的复杂度会掩盖真正该做的事。删掉不是减法，是把注意力挪回能落地的地方。

### 5.1 `CASE_LINE` / `LINE_CASE`：测试点 ↔ 代码行映射

**它是什么**：`s-workbench.js:14` 的 `const CASE_LINE = { 1: 15, 2: 15, 3: 8, 4: 8, 5: 13, 6: 12, 7: 9, 8: 8, 9: 12, 10: 9 }`，把 10 个测试点编号映到编辑器里的行号；`s-workbench.js:16` 的 `const LINE_CASE = { 8: 3, 9: 7, 12: 6, 13: 5, 15: 1 }` 是反查表。点"第 3 个测试点失败"就高亮第 8 行，点第 9 行就高亮第 7 个测试点。

**为什么必须删**：`s-workbench.js:10-13` 的注释自己承认——"真实判题系统不会给这种映射，原型里它是叙事道具"。判题容器拿到的是 `cmd`、`copyIn` 与限值，跑完只回状态、耗时、内存；**没有任何一环能知道"第 8 行的代码导致第 3 个测试点失败"**。要做这个能力需要逐行插桩或符号执行，那是另一个课题。它现在的唯一作用是让演示看起来"聪明"，代价是给评委一个可以当场证伪的点。

**删了之后用什么替代**：

| 原表现 | 替代 | 依据 |
|---|---|---|
| 点测试点 → 高亮"相关行" | 点测试点 → 右侧面板展示该点的**输入/期望输出/实际输出**三栏 diff | 契约 `caseDetails` 已有 `caseId/status/timeMs/memKb`，补 `input/expected/actual` 三字段即可 |
| 点代码行 → 高亮"相关测试点" | 点代码行 → 只显示行号与断点态（编辑器自身能力，不谎称与判题相关） | 编辑器手写 17 行，不引入 Monaco |
| `focusLine` getter(`:71`) 与 `focusFromLine()`(`:207`) | 改为 `focusCase`（测试点维度），`clearFocus()`(`:206`) 保留 | 测试点维度是真实的，行维度是编的 |

改造动作：删 `CASE_LINE`(`:14`)、`LINE_CASE`(`:16`)、`focusLine` getter(`:71`)、`focusFromLine()`(`:207`)；模板里 `s-workbench.html:165/171/192/196/198/201` 六处 `:class="{'is-focus':focusLine===N}"` 改成 `:class="{'is-focus':focusCase===N}"`（**class 名不动，只换判定源**）。`s-workbench.html:153` 那句"联动高亮"的注释文案要一起改。

### 5.2 `REPLIES{1..9}`：9 条硬编码 AI 回复

**它是什么**：`s-workbench.js:20-30` 的九条固定文本，`ask()`(`:222-241`) 按 `this.fixed ? (this.stage === 4 ? 7 : 6) : 5` 选一条，820ms 后 push 进聊天气泡。**回复与用户输入完全无关**——输入"这段代码为什么 TLE"和输入"你好"，拿到的是同一段话。

**为什么必须删**：这是全站唯一一处"看起来有 AI、实际没有 AI"的地方，而 AI 对话恰恰是论文的核心创新点。评审只要在两个输入框里打两句不同的话，立刻能看出回复一模一样。更严重的是它掩盖了四个真实工程问题：SSE 六事件怎么分发、降级怎么提示、护栏改写怎么标注、配额怎么由服务端控制——这四件事在 `REPLIES` 存在时一件都不需要面对。

**删了之后用什么替代**：`api.sse('/api/ai/chat/stream', {...})` 的六事件处理（§2.3）。逐项对应：

| `REPLIES` 键 | 现在的内容 | 替代事件链 |
|---|---|---|
| 1–4（初始四阶段引导） | 四段固定引导语 | `router_step` → `token`(多次) → `done` |
| 5（一般提问） | 通用鼓励话术 | `router_step` 定 `stage` → `tool_calling`（检索相似题）→ `token` |
| 6（已修复后提问） | "你已经改对了…" | `router_step(stage=3)` → `token` → `done(remainingQuota)` |
| 7（AC 后复盘） | "复盘要点…" | `router_step(stage=4)` → `token` → `done` 解锁阶段四 |
| 8–9 | 降级/超限提示 | `fallback_notice`（降级）/ `error(429)`（配额耗尽） |

原来 `ask()` 里三件事要跟着改：`replying` 改由 `done`/`error`/`fatal` 复位（不是 820ms 定时器）；`chat` 的 AI 气泡要有"正在输入"与"已中断"两个中间态；`quotaLeft` 只在 `done` 事件里写（§5.3）。

### 5.3 `quotaLeft` 前端自减 + `submit()` 重置

**它是什么**：`s-workbench.js:48` 的 `quotaLeft: 2`；`ask()` 里 `:227` 的 `this.quotaLeft = Math.max(0, this.quotaLeft - 1)`；`submit()` 里 `:127` 的 `this.quotaLeft = 2`——**每次提交都把配额重置回 2**。

**为什么必须删**：三处独立错误叠在一起。① **配额是计费与公平性约束，只能由服务端裁决**；前端自减等于用户改一行 JS 就无限用。② `submit()` 重置配额意味着"提交一次就白送一次 AI 机会"，而这个重置**没有任何业务含义**，纯粹是原作者为了让演示能反复跑。③ 初始值 `2` 与契约的 `remainingQuota:2 / maxQuota:3` 只是碰巧相等，一旦服务端策略调整（比如考试模式全关、作业模式上限 3 次），前端数字立刻与现实不符，而页面上还写着"本题还剩 2 次"（`s-workbench.html:507`）与"2 / 3"（`:541`）。

**删了之后用什么替代**：

| 时机 | 数据来源 | 写哪个字段 |
|---|---|---|
| 进入工作台 | `GET /api/ai/workspace-init` 的 `remainingQuota` / `maxQuota` | `quotaLeft` / `quotaMax` |
| 每次对话结束 | SSE `done` 事件的 `remainingQuota` | `quotaLeft`（**唯一写入口**） |
| 配额耗尽 | `error` 事件 `code===429` | `quotaLeft = 0` + 禁用输入框 |
| 提交判题 | **不碰** `quotaLeft` | — |

页面文案不改结构：`s-workbench.html:507` 的 `<b x-text="quotaLeft">2</b>` 与 `:541` 的 `<b x-text="quotaLeft+' / 3'">2 / 3</b>` 只是数据源变了；把 `' / 3'` 改成 `' / ' + quotaMax` 即可（仍是同一个 `<b>`）。`AI 策略全关`的场景（考试模式 `403`）由 `workspace-init` 的 `aiEnabled: false` 驱动，走已有的 `.note` 提示条，不新造组件。

### 6.2 `visibilitychange`：考试切屏监听

**现状**：`s-exam.html` 全文 `visibilitychange` 与 `blur` **零命中**；页面上写着"切屏超过 3 次记为异常"(`s-exam.html:235`)，但交卷弹窗里"切屏次数"写死 `0`(`:368`)。这项考试纪律的核心功能，原型里只是一句文案。

```js
/* s-exam.html 的 examPage() 内新增 */
tabSwitchCount: 0, tabSwitchLimit: 3, awayAt: 0, reporting: false, violation: null, pendingSwitches: [],

init() {
  /* …既有 init 保持不动… */
  var self = this;
  this._onVis = function () { document.hidden ? self.handleHidden() : self.handleVisible(); };
  document.addEventListener('visibilitychange', this._onVis);
},
handleHidden() {
  if (this.submitted || this.loading || this.loadErr || this.awayAt) return;   // 只在进行中计数
  this.awayAt = performance.now();                                            // 不用 Date.now()：系统改时间会算错
},
handleVisible() {
  if (!this.awayAt || this.submitted) return;
  var awaySeconds = Math.round((performance.now() - this.awayAt) / 1000);
  this.awayAt = 0;
  if (awaySeconds < 3) return;                                                // 契约：<3 秒不计数，防误触地址栏
  this.reportSwitch(awaySeconds);
},
async reportSwitch(awaySeconds) {
  if (this.reporting) return;                                                 // 防抖：连点两次只发一次
  this.reporting = true;
  try {
    var r = await api.teaching.tabSwitch({
      assignmentId: this.assignmentId, problemId: this.curProblemId, awaySeconds: awaySeconds
    });
    this.tabSwitchCount = r.tabSwitchCount;                                   // 始终以服务端为准，前端不自增
    this.tabSwitchLimit = r.limit;
    if (r.redFlagTriggered) this.violation = { level: 'red', msg: r.alertMessage || '切屏已达上限，本次记为异常' };
    else if (r.tabSwitchCount >= r.limit - 1) this.violation = { level: 'warn', msg: '已切屏 ' + r.tabSwitchCount + ' 次' };
  } catch (e) {
    this.pendingSwitches.push({ awaySeconds: awaySeconds, at: Date.now() });   // 失败不阻塞答题，下次补报
  } finally { this.reporting = false; }
},
destroy() { if (this._onVis) document.removeEventListener('visibilitychange', this._onVis); }
```

四个边界：**切屏后直接关标签页** → `pagehide` 里用 `navigator.sendBeacon('/api/teaching/exam/tab-switch', blob)` 补报，不用 fetch（页面卸载时会被取消）；**切屏后断网** → 进 `pendingSwitches`，下次 `reportSwitch` 成功时先 flush；**交卷后切屏** → `submitted` 直接 return；**同一秒内连续切** → `reporting` 标志位挡住并发。

UI 落点（**不改 DOM**）：`s-exam.html:368` 的 `<dd>0</dd>` 改成 `<dd x-text="tabSwitchCount">0</dd>`；`:235` 的"切屏超过 <b>3 次</b>"把 `3` 换成 `<b x-text="tabSwitchLimit">3</b>`；`violation` 提示复用已有的 `.note.warn/.note.err`，`x-show="!!violation"` 挂在 `.page-head` 之后。

**工作台也要装**：`s-workbench.js` 的练习态同样监听——契约该接口对练习/作业/考试三种 `modeType` 都生效，只是 `redFlagTriggered` 仅考试为 true。学生在工作台停留最久，切屏数据是教师端学情的重要输入。

### 6.3 轮询与 SSE 的生命周期

**现状**：`t-monitor.html:761-774` 的 `init()` 有两个 `setInterval`（`:765` 的 1 秒倒计时、`:773` 的 8 秒造事件），**都没有 `clear`**；`s-exam.html:616-629` 的倒计时也没清；`a-audit.html` 的 `autoRefresh: true` 甚至没有定时器（纯视觉开关）。

四条规则：

| 时机 | 轮询（`api/poll.js`） | SSE（`api/sse.js`） |
|---|---|---|
| **何时启** | 提交成功后 / 进入监考页后，在 `init()` 里 `start()` | 用户点"发送"后立即 `api.sse(...)` |
| **何时停** | `status >= 3`（终态）/ 次数上限 / 401·403·404 / `destroy()` | `done` 事件 / `[DONE]` / `fatal` / `destroy()` / 用户切换话题 |
| **页面隐藏** | `clear()` 停表，回前台先补一次再续 | 不中断（AI 正在吐字，切走一秒回来不能断片） |
| **销毁清理** | `poller.stop('dispose')` + 摘 `visibilitychange` | `sseHandle.close()`（内部 `ctrl.abort()` + 摘监听） |

Alpine 3 没有 `destroy` 生命周期钩子，用 `x-init` 返回清理函数不是官方语义，所以统一在组件里显式定义 `destroy()`，由 `boot.js` 在 `beforeunload` 时遍历当前组件调用：

```js
/* boot.js 尾部 */
window.addEventListener('beforeunload', function () {
  var root = document.getElementById('page-content');
  var data = root && window.Alpine && Alpine.$data ? Alpine.$data(root) : null;
  if (data && typeof data.destroy === 'function') data.destroy();
});
```

`Alpine.$data(el)` 是 Alpine 3 的公开 API，能拿到 `x-data` 对象本身；拿不到就静默跳过（`vendor` 目录里是压缩版，不保证所有小版本都暴露该 API），最坏情况是页面卸载时定时器随文档一起销毁——不会泄漏到下一个页面，因为这是个多页应用，每次跳转都是新的 document。

## 9. 风险与对策

| # | 风险 | 触发条件 | 影响 | 对策 |
|---|---|---|---|---|
| R1 | **SSE 断线** | 网关 60s 空闲超时、Nginx 缓冲、模型侧卡住 | 气泡停在半句，用户以为卡死 | 首字 15s 超时守卫 + `maxRetries:2` 退避重连 + 断线时气泡标"已中断，点击重试"；`X-Accel-Buffering: no` 关掉代理缓冲 |
| R2 | **轮询风暴** | 多人同时提交，或 `setInterval` 堆积 | 网关 429、判题服务排队雪崩 | 只用 `poll.js`（禁 `setInterval`）；1s 起、退避到 5s、上限 120 次；页面隐藏暂停；终态即停；后端按 `submissionId` 做 1s 结果缓存 |
| R3 | **`?mock=1` 与真实数据混用** | 演示中途去掉参数，或 `localStorage` 残留 | 一半列表真实一半假，数据对不上 | mock 判定收敛到 `http.useMock()` 单一入口；切到真实时清 `sessionStorage.OJ_USE_MOCK`；页面上常驻一个"演示模式"角标（复用 `.badge`），让状态永远可见 |
| R4 | **`shell.js` 改动波及 14 页** | 删常量、改 `mount()`、改 `NAV` | 全站崩，且因为无构建产物无法回滚单页 | 先加 mock 再删常量（两 commit）；每改一次跑 16 页截图脚本；`OJ` 工具对象的签名一律只增不改 |
| R5 | **Alpine 响应式对数组替换失效** | `this.list = newArr` 在旧对象上继续 `x-for`，或原地 `push` 不触发 | 列表不刷新，或出现重复行 | 统一整组替换（`this.list = d.list.map(...)`），禁止原地 mutate；`x-for` 必须有 `:key` 且 key 用稳定 `id`（`a-models.html:512` 用 `at` 当 key 是反面教材） |
| R6 | **状态枚举错位** | 把 `status` 整型直接塞进 `OJ.statusTag` | 全站 `.tag` 裸奔，视觉全崩 | 模板里一律传 `statusCode`；加一条 grep 检查：`OJ.statusTag(` 后不得出现 `.status` |
| R7 | **`display_no` 撞车** | 题目 `P-1024` 与查重 `P-0088` 同前缀 | 详情页跳错对象 | 前端永不自拼单号，统一走 `adapter.displayNo`；路由用 `id` 不用 `display_no` |
| R8 | **两页学情数据同源** | `s-analytics` 与 `t-analytics` 的 pct 都是 82/64/41/73/55 | 评审一眼看穿是同一份假数据 | 接真实接口后自然分离；在此之前 mock 里给两侧不同随机种子，并加注释说明 |
| R9 | **`weak_tags` 与 `KP_BASE` 语义反向** | 一个"越高越弱"、一个"越高越强" | 掌握度图表读反 | 由服务端统一输出 `mastery`（越高越强），前端只认这一个字段；命名里不允许出现 `weak` |
| R10 | **定时器泄漏** | `t-monitor` 两个 `setInterval`、`s-exam` 倒计时都不 `clear` | 长时间停留后内存涨、并发请求翻倍 | 全部改用 `poll.js`/单一定时器 + `destroy()`；`boot.js` 在 `beforeunload` 兜底调 `destroy()` |
| R11 | **时区与本地时间** | 后端 UTC epoch、前端 `new Date(ms)` 用本地时区 | 截止时间差 8 小时，作业显示"已结束" | 全站只用 `adapter.fmtDateTime/leftText`（内部统一 `new Date(ms)` 本地渲染）；服务端一律传 epoch，禁止传格式化字符串 |
| R12 | **后端 9 端点不够用** | 阶段 3–5 需要 87 个端点 | 前端写完没接口可调 | 严格按 `02-契约补全规范-v2.0.md` 的增量清单推进；前端先把 `mock.js` 的 ROUTES 写全，接口到位后逐个删 mock 分支——**mock 先行的顺序不能反** |

### 最后三条提醒

1. **先跑通 `?mock=1`，再谈对接**。16 页在 mock 下全部可交互之后，接真实接口只是"换数据源"，一天能改两三页；反过来先接接口，每页都会卡在"数据不对但不知道哪不对"。
2. **任何"看起来很聪明"的演示逻辑都要能回答"这个数据哪来的"**。`CASE_LINE`、`REPLIES`、`quotaLeft` 三处已经踩过，改造时不要再造第四个。
3. **`_SPEC.md` 的 12 条设计硬规则是验收线，不是建议**。尤其"必须写空态"与"状态切换不改尺寸"——接真实数据后最容易破的就是这两条。
