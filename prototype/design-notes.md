# 原型设计说明 · 启发式智能在线判题系统

## 0. 已确认的事实

- 产品：基于 AI Agent 与微服务架构的启发式智能在线判题系统（毕业设计）。
- 风格基线（用户已敲定，来自《系统详细设计》开篇）：现代清爽亮色风，全局清爽白 + 科技蓝；Monaco 支持一键切暗黑。
- 技术栈基线：Vue 3 + Vite + Pinia + Element Plus + Monaco + ECharts + Fetch EventSource。
- 目标视口：桌面 1440×900 为主，兼顾 1280；截图用于论文与答辩投影，按 2× 出图。
- 原型形态：先做可直接打开、可截图的高保真 HTML/CSS/JS 小样，交付时给 Vue + Element Plus 的迁移映射。

## 1. 认品类、拆标杆

**品类**：在线判题系统（OJ）的做题工作区，以及配套的教学管理台。这是高频专业工具 + 教学内容页的混合体。

- LeetCode 中国站 · 做题页 —— `research/two-sum.png`
- 洛谷 · 题目页 —— `research/P1001.png`

### 拆 LeetCode 中国站（对着 two-sum.png）

| 看见的要素 | 为什么这样做 |
| --- | --- |
| 顶栏单行约 44px，工具图标（设置/运行/提交）贴中线，无大标题 | 做题时工具必须一直在视线内，但不许占高度 |
| 左右各 50%，中缝约 4px 可拖拽，无卡片、无阴影、无圆角容器 | 高频专业工具用分隔线分层，卡片会吃掉内容宽度 |
| 题面 15px / 行高 1.75，段间 16px | 中文长文可读，但不追求阅读舒适度 |
| 示例块浅灰底 + 2px 左竖线，输入输出等宽 | 示例是要复制的数据，等宽才扫得快 |
| 全灰阶，唯一彩色是"提交"绿与难度胶囊；品牌色退到 logo | 颜色预算全留给状态 |
| 底部"测试用例 / 测试结果"页签可拖高 | 结果面板按需出现，不常驻 |

### 拆洛谷（对着 P1001.png）

| 看见的要素 | 为什么这样做 |
| --- | --- |
| 左侧约 60px 线稿图标导航，选中为蓝图标 + 浅蓝底块 | 学生常驻导航，图标比文字省宽 |
| 圆角 12px 白卡片浮在浅蓝手绘插画背景上 | 面向学生，亲和、不压迫 |
| 标题卡同一层放四个参数：提交 / 通过 / 时限 / 内存 | 决定"要不要做"的关键数字必须和标题同一视觉层 |
| 右侧 300px 独立信息卡：编号、难度、标签、讨论、推荐 | 元信息与正文分离，正文宽度不被挤 |
| 页签用 2px 蓝色下划线，按钮 4px 圆角实心蓝 | 控件语法统一、克制 |

### 留什么、换什么

- **留（LeetCode）**：无卡片分隔、中缝可拖拽、示例等宽块、工具条单行——做题是高频操作，装饰会占掉内容宽度。
- **留（洛谷）**：标题层带时限 / 内存 / 测试点数——我们的题有 N 个隐藏测试点，这是 OI 赛制特有的参数，必须同层可见。
- **换（洛谷）**：插画背景与大圆角卡片。论文截图与答辩投影需要"系统感"，插画会削弱技术可信度；但也不能走 LeetCode 的冷淡灰。
- **换（LeetCode）**：两栏不够。要容纳 AI 助教，但三栏不能均分——题目可读性优先。
- **两家都没有的**：判题过程可视化（OI 按点计分 / 首失败点）与 AI 多智能体协同过程可视化。这是本产品的差异空间，也是记忆点所在。

## 2. 调性（五刻度，三个方向共用）

| 刻度 | 取值 | 依据 |
| --- | --- | --- |
| 能量 | 安静偏中 | 学习与考试场景，低饱和；但 AI 协同要有活力 |
| 完成度 | 精致 | 论文截图与答辩演示要求高完成度，公差要小 |
| 密度 | 中等偏密 | 做题工作台是高频工具；教师端更密 |
| 分量 | 轻中 | 亮色、细描边、浅阴影 |
| 严肃度 | 中 | 学术工具，AI 助教可亲和但不卖萌 |

## 3. 色彩基线（用户锁定科技蓝后）

- 品类默认：白底 + 蓝/绿强调（LeetCode 绿、洛谷蓝）。我们沿用蓝，但把它从"品牌点缀"升级为"链路语义色"。
- 三层：
  - 底色 `#FFFFFF` / 面板底 `#F8FAFC` / 暖白备选 `#FAFAF9`
  - 主强调 `#2563EB`；派生：选中底 `#EFF6FF`、描边 `#DBEAFE`、深蓝文字 `#1E3A8A`、禁用 `#94A3B8`
  - 状态色：AC `#16A34A`、WA `#DC2626`、TLE `#EA580C`、CE/未知 `#7C3AED`
- 文字：主 `#0F172A`、次 `#475569`、弱 `#94A3B8`。

## 4. 三个方向

首屏小样：`prototype/explore/{a,b,c}/index.html`；对比页：`prototype/explore/style-explorer.html`（可直接打开，点「选择」回报编号）。

### A · 判分链（`explore/a/`）

- **一句话**：让「每一分是怎么丢的」当场可见。
- **页面结构**：单屏不滚动。左 316px 题面（输入示例、隐藏点计数、知识点标签）· 中 Monaco 编辑器（行号槽直接标红）· 右 360px 判题栏（分数 88/100 大字 + 三个横向条：耗时 / 内存 / 失败点）。**底部常驻 10 格测试点链带**，每格一个编号 + 毫秒数，失败格变红、拉宽 3 倍、上浮带指针。
- **结构性突破**：把"结果页签"变成常驻的**链带**。OI 按点计分，10 个点就是 10 个分数来源，它们应该在打字时就在视线下方，而不是提交后才展开。
- **记忆点**：10 格里第 3 格红得扎眼、比别的宽——「第 3 号测试点，-1 -2 -3，你输出了 0」。
- **动效**：提交后链带从左到右逐格点亮（每格 60ms），到失败格停住并轻微抖动一次。
- **AI 的位置**：收成右侧 64px 轨道上的一个胶囊，点开才展开成浮层。AI 不占常驻宽度——做题时人主要看代码。
- **放弃什么**：放弃"AI 全程在场"。学生做题时最需要的是安静的判分反馈，AI 是叫了才来的。

### B · 批注课堂（`explore/b/`）

- **一句话**：AI 不占一栏，它像老师的批注一样长在它所指的地方。
- **页面结构**：两栏。左 55% 题面（衬线标题、暖白纸感、示例块浅米底）· 右 45% 编辑器。**没有聊天框**。AI 的话以**批注气泡**形式出现在代码行号右侧，从行号牵一条 1px 细线到气泡，气泡有手写感的引线端头。
- **结构性突破**：AI 回复不再是一个"对话流"，而是**代码上的锚点集合**。同一个学生第二次犯错，批注会落在同一行——这本身就是学习记录。
- **记忆点**：编辑器右边缘垂下一排黄色便签，每张都对着一行代码。关掉一张，那行的背景高亮也一起消失。
- **动效**：气泡从行号位置 0.3s 内"长"出来（scaleY 0→1，origin 在引线端）。
- **判题结果**：只给一行摘要（"10 个点过 9，第 3 个 WA，-1 -2 -3 应为 -1"），不铺格子——格子留给 A 方向。
- **放弃什么**：放弃"一次看完全部过程"。学生点开一张便签才看一张，理解是被迫逐条的。

### C · 协同面板（`explore/c/`）

- **一句话**：让 Multi-Agent 的协同过程成为界面的一部分。
- **页面结构**：三栏。左 300px 题面 · 中 Monaco · 右 380px「智能体工作台」。工作台顶部是**模型切换**（本地极速 Qwen2.5-Coder 7B / 云端 DeepSeek，附"云端超时自动降级到本地 Ollama"说明）；下面是**竖直流水线**：Router（已识别阶段）→ Tutor（进行中，含工具调用 `getFailedTestCaseFeature(1024)` 与参数、耗时、进度条）→ Guardrail（等待审查，写明规则"回复不得出现超过 5 行完整解题代码"）。最下方才是**回复内容**，标注"已生成 2 段 · 待护栏审查"。
- **结构性突破**：把**过程层和内容层分开**。学生看到的不只是答案，而是"谁在什么时候用什么工具得出了它"。这直接对应毕设的技术贡献（多智能体编排 + 护栏）。
- **记忆点**：Router/Tutor/Guardrail 三个节点连成的竖线，当前节点是实心紫环，已完成是绿勾——一眼看出系统跑到哪一步。
- **动效**：进度条推进 + 当前节点呼吸；Guardrail 审查通过时虚线框变实线并打勾。
- **放弃什么**：放弃"干净"。这个方向信息密度最高，是三个里最"工程可视化"的，适合答辩演示，但日常做题略吵。

### 横向对比

| | A 判分链 | B 批注课堂 | C 协同面板 |
| --- | --- | --- | --- |
| 差异点押在 | 判分可视化 | AI 回复的形态 | 智能体协同过程 |
| 栏数 | 3（窄右栏 + 底部链带） | 2 | 3（右侧重） |
| AI 常驻？ | 否，胶囊 | 否，批注 | 是，整栏 |
| 最适合的场合 | 学生日常刷题 | 教学/一对一辅导 | 答辩演示技术亮点 |
| 风险 | 链带占了编辑器高度 | 批注多了会挤编辑器 | 右侧太重，挤压题面 |

### 三轮整改后的定稿事实

- **版式**：16 页统一「主角 → 扁平统计带 → 明细面板」三级；每页只有一个 44px 主角（`t-dashboard` 是「需要你处理」待办卡，主角未必是数字）。
- **令牌**：文字色三级实色 + 一级虚线色；字号 11/12/13/14/16/22/30/44 连续台阶；卡片圆角 12px。
- **共享层**：判分链（`.vchain`）、骨架屏（`.skeleton`）、抽屉退场、页面进场错峰都已在 `components.css`，页面只写内容。
- **可访问性**：全站三档截图 lint 无对比度问题；`/` 搜索、`?` 快捷键表、`Esc` 关弹层；reduced-motion 按组件关闭而非一刀切。
- **仍未做**：移动端适配（原型按桌面评审）；题库/作业的分页是前端模拟。
